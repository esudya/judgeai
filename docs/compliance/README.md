## Обновление без Docker, сети и секретов

Нужен Python 3.11 или новее; дополнительная библиотека не устанавливается:

```bash
python3 -m unittest discover -s tests_unit -v
python3 tools/dependency_inventory.py
python3 tools/dependency_inventory.py --check
```

`--check` ничего не записывает и возвращает ненулевой код, если артефакты устарели или входы некорректны. Генератор читает фиксированные публичные манифесты и реестры; тест проверяет полный список прочитанных файлов. `.env`, файлы cookie/токенов, загрузки и приватные примеры не читаются. URL с пользовательскими данными, fragment или произвольными query-параметрами отклоняются без печати их значений. Разрешены только конкретные публичные параметры выгрузки pravo.gov.ru/ВС с проверкой значений. Python direct-URL зависимости требуют отдельного разбора происхождения, автоматически не экспортируются.

При изменении зависимостей/модели: сначала проверить первичные документы, обновить evidence/resources, затем перегенерировать артефакты и выполнить `--check`. Новая библиотека без лицензионного evidence вызывает ошибку. При слиянии T10 потребуется учесть Argon2; отсутствие этой ещё не влитой зависимости в текущем срезе не означает её юридического одобрения. При изменении модели в T8/T26 её владельцы добавляют ревизию/хеш и источники прав; данный MR модель не выбирает.

Валидация текущего SBOM: официальная [JSON-схема CycloneDX 1.6](https://cyclonedx.org/schema/bom-1.6.schema.json), Git blob `b6c096a999d6ee9e408a9c3ae6c6227d6981c9ba`, вместе с её spdx/jsf-схемами. Схемы и уже кешированный валидатор использованы только локально для проверки; в зависимости продукта не добавлены. SBOM прошёл схему; контрольный документ без bomFormat отвергнут валидатором. Генератор не выдаётся за универсальный валидатор CycloneDX; отдельная schema-validation обязательна после изменения формата генератора.

Лицензия кода обёртки, правила web-сервиса и права на модель — отдельные вопросы. Ни локальность proxy, ни совместимый HTTP API не подтверждают права на модель или допустимость передачи реальных дел. Условия распространения/сетевого использования обёртки требуют разбора перед внедрением; вывода об автоматическом лицензировании всего JudgeAI здесь нет.
- [RusLawOD](https://huggingface.co/datasets/irlspbru/RusLawOD) сейчас помечен в карточке CC-BY-NC-4.0. Ранние заметки проекта содержат NC-SA-вариант: перед импортом нужно сверить условия конкретного релиза и назначение использования. В этом этапе корпус не скачивался.
- [ru-law-retrieval](https://huggingface.co/datasets/alekseevpavel04/ru-law-retrieval/raw/main/README.md) указывает mixed-see-card: юридические тексты, сгенерированные вопросы и разметка имеют разные условия. Общая надпись MIT для всего набора была бы необоснованной. Корпус здесь не импортировался.
- Официальные источники уголовного пилота перечислены с SHA-256 в [legal-sources.json](../legal-sources.json). Этот инструмент проверяет формат реестра, не перечитывает локальные архивы и не подтверждает редакции. Правовой статус официального текста нельзя переносить автоматически на оформление сайта, комментарии, чужую базу данных или персональные сведения в приговорах.

## Воспроизводимая установка: что ещё требуется

Frontend: выполнять `npm ci` по имеющемуся package-lock.json в отдельном чистом окружении с зафиксированными Node/npm/OS/архитектурой, затем тесты и сборку. Optional/platform-пакеты зависят от среды, поэтому одинаковый lockfile сам по себе не доказывает побайтовую идентичность итогового bundle.

Backend: диапазоны `>=` и extras не являются lockfile. В утверждённом целевом окружении нужно разрешить **всё** дерево зависимостей, зафиксировать версии и SHA-256 дистрибутивов, отдельные runtime/dev/build наборы и выполнить чистую установку с `--require-hashes`. Нельзя формировать фиктивный lockfile из нижних границ диапазонов или выдавать случайный pip freeze другого проекта за состав JudgeAI. Здесь такой подмены нет; Docker-окружение не инспектировалось.

Образы: зафиксировать digest/платформу Python и PostgreSQL/pgvector, перечень OS/build-пакетов и их условия; проверить повторную сборку. Модель: зафиксировать commit и хеши весов/токенизатора. Удалённый сервис: зафиксировать договорные условия, заявленную модель, параметры и ограничения воспроизведения ответов. SBOM исходников не заменяет SBOM контейнера/развёртывания.

## Решения владельца и статус T19

**T19 остаётся частично выполненной.** До полного DoD нужны resolved Python/image/model инвентарь, проверка прав на данные и поставку компонентов, согласованные замены при необходимости и выбранная владельцем лицензия самого проекта. Файл LICENSE в этом MR не создаётся. Нельзя на основании списка MIT-зависимостей автоматически выбрать MIT для проекта или признать право на чужие данные.

Следующий конкретный шаг — согласовать целевую платформу установки и получить SBOM фактического контейнера; затем разобрать открытые ограничения и выбрать лицензию своего кода. Никакого деплоя, изменения провайдера или разрешения на внешнюю передачу дел этот документ не даёт.

Проверка реализации: **12/12** автономных тестов, линтер, Python-компиляция, read-only check-mode и официальная JSON-схема прошли. Независимое ревью обнаружило пропуск подписанных query/fragment и неточных npm-версий; оба исправлены с воспроизведением отказов до изменений и зелёным повторным прогоном. Полные API/БД/browser-тесты для этой ветки не выполнялись: исполняемый код приложения не менялся.


Argon2-cffi добавлен авторизацией: upstream MIT LICENSE проверен по Git blob d1b626b36530035f4a816de74e4adec2f0b6f655. Точные runtime/transitive версии по-прежнему не выдаются за подтверждённый resolved SBOM; прогресс и приёмка только в TASKS.md.
