# Протокол автозапуска

Каждые 5 часов запускается новая сессия Claude. Она не помнит прошлые — вся память в `docs/TASKS.md` и git.

## Окружение
- GitLab: `judgeai/judgeai`. План читать из `main`. Каждый запуск создаёт свою ветку `auto/<Tn>-<короткое-имя>` от свежего `main` (add_commit с start_branch=main) и пушит туда код и обновлённый TASKS.md. Ветки в команде мержат быстро и удаляют — не рассчитывай на старую ветку. Если предыдущая `auto/*` ветка ещё не смержена — строй от неё, а не от main. `main` защищена: в неё не пушить и самому не мержить; MR можно открыть.
- Репозиторий на Mac: `/Users/alexsho/Documents/05_PROJECTS/LETI/ПРАВО/judgeai` (дерево = main по состоянию на 27.10). Перед работой сверить `docs/TASKS.md` на Mac с версией в GitLab-ветке; источник правды — GitLab.
- В облачном контейнере закрыты pip, npm и git до GitLab. Установка пакетов, тесты и Docker — только на Mac.
- Команды на Mac: через `device_bash`, если доступен; иначе через osascript `do shell script` (длинные процессы: `cd X; nohup cmd > log 2>&1 < /dev/null &`, без `&&` перед nohup). Файлы на Mac писать через device_commit_files (каждый раз новый stagedPath).
- Тесты api: `docker compose run --rm api pytest` (db на 127.0.0.1:55432, override-файл локальный).
- Push: `git push` с Mac не работает (нет ключа). Пушить через GitLab MCP `add_commit` в ветку, затем сверить содержимое файлов.

## Правила
0. **Никакого хардкода данных (требование пользователя).** Все данные, которые видит пользователь или на которые опирается анализ, берутся из БД: санкции статей, практика, статистика, списки дел, результаты. В БД данные попадают только импортёром из реального источника с происхождением (url, редакция, дата загрузки). Фронт работает только через API; моки (`VITE_USE_MOCKS`) не попадают в сборку и демо. Фейковые данные допустимы только в тестах (фикстуры). Логика норм УК (как считать ст. 68 и т. п.) — бизнес-правила в legal_core, не данные; конкретные санкции и редакции — данные в БД. Захардкоженное сейчас (фейк LLM как источник результата, моки фронта, санкции в коде) вынести в БД/фикстуры в рамках соответствующей задачи.
1. Одна задача за запуск. TDD: тест → код → рефакторинг. Покрытие ≥ 80%.
2. Не ломать работающее: удаление — только с заглушкой `TODO` и пометкой в журнале.
3. Никаких секретов в коде/коммитах/логах. Ключ LLM — только `.env` (не коммитится).
4. Приватные образцы (`ПРАВО/judgeai-private/`) — не коммитить, не пушить, не цитировать.
5. Не переписывать историю git, не force-push, не мержить в main, не деплоить.
6. Схема БД — только новой миграцией с описанным downgrade.
7. Тест/линтер красный — не коммитить; записать в журнал и оставить задачу `[~]`.
8. В конце: обновить TASKS.md (статус + журнал), запушить, отчёт по-русски: что сделано, что проверено, что не вышло, что дальше.
9. Если Mac недоступен — сделать только задачи «можно без Mac» (T1, частично T5 — сбор данных санкций), результат запушить через GitLab MCP.
10. Все задачи `[x]` → отключить свой scheduled task (update_trigger enabled=false) и написать итоговый отчёт.
