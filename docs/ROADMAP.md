# Цифровой судья — архитектурный план (v3, 27.10.2026)

Продукт: «второе мнение» на **проект приговора** судьи (конкурс ВС «Алгоритм правосудия. Второе мнение»).
Фокус: рецидив — ст. 15, 18, 68 УК (+ 62, 63, 73, 86, 58). Система решений не принимает (п. 2.5.3 Положения).
Дедлайн I этапа — 01.11.2026 (рабочий сайт). Финал — март 2027.

## Источник требований и статус плана

Карта соответствия приложенной концепции: [CONCEPT_ALIGNMENT.md](CONCEPT_ALIGNMENT.md), пункты C01–C17. Там отделены требования DOCX, ранее выбранный пилот и предложения, требующие решения перед реализацией. Основной сценарий: **проверить уже назначенное наказание в загруженном проекте приговора**. Генерация нового приговора не заменяет эту задачу.

Конкурсные сроки выше — ранее записанные ориентиры; в приложенном DOCX они не указаны и заново не проверялись. Подгонка под срок не отменяет юридическую приёмку и безопасность.

## 1. Ранее записанные инженерные решения (27.10)

| Вопрос | Решение |
|---|---|
| Раскладка | Монорепо `judgeai`: `apps/web`, `services/api`, `services/parser`, `packages/legal_core` |
| Архитектура | Clean Architecture: domain → application (use cases) → adapters (интерфейсы, контроллеры, репозитории) → infrastructure (ORM, HTTP, LLM SDK, парсеры файлов). Бизнес-логика не знает про FastAPI/SQLAlchemy/LLM |
| Тесты | TDD (red → green → refactor). Порог покрытия **80%** (`pytest --cov-fail-under=80`) на каждый Python-пакет |
| Авторизация | Логин + пароль (argon2), сессионный токен. Без внешних провайдеров. Каждый use case принимает `UserContext`; доступ к чужому делу → `AccessDenied` (тест обязателен) |
| Тенантность | База практики (precedents) — общая, только чтение. Дела пользователя (проекты приговоров, отчёты) — строго по `owner_id` |
| LLM | Любой OpenAI-совместимый провайдер за `LlmGateway`. Промпты — только в infrastructure. Перед отправкой — обезличивание в application (`Anonymizer`) |
| Асинхронность | Статусы задач `pending/processing/completed/failed` в домене; очередь за интерфейсом `TaskQueue` (сейчас in-process BackgroundTasks, позже — брокер) |
| Деплой | Только локально. Публичный деплой — только после явного «да» пользователя |
| Приватные образцы | 9 неотбезличенных приговоров лежат в `ПРАВО/judgeai-private/samples/` — **вне репозитория**. Никогда не коммитить, не пушить, не цитировать ФИО в логах/тестах. Для тестов — синтетические фикстуры, сделанные по их структуре |

## 2. Монорепо

```
judgeai/

    legal_core/
      entities/                 # Conviction, CriminalRecord, Sanction, Punishment, DraftVerdict, ...
      rules/                    # одна норма = один модуль: art15_category.py, art18_recidivism.py, art68.py, art62.py, art63.py, art73.py, art86.py, art58.py
      checks.py                 # CheckResult(status: ok|possible_violation|insufficient_data, norm, explanation, quote)
    tests/
  services/parser/              # Сбор и нормализация практики
    parser/
      domain/                   # RawDecision, PrecedentCard, SourceId
      application/              # CrawlSource, NormalizeDecision, Deduplicate
      adapters/                 # SourceCrawler (Protocol), DecisionRepository (Protocol)
      infrastructure/           # sudact.py, sudrf.py, http_client (rate limit, robots), storage (fs + Postgres)
    tests/
  services/api/                 # Текущий FastAPI-бэкенд, переносится сюда из корня
    src/
      domain/  application/  adapters/  infrastructure/
    tests/
  apps/web/                     # Текущий фронт (verdikt-web)
  docs/  ROADMAP.md  TASKS.md  AUTORUN.md  data-sources.md
```

`services/api` и `services/parser` импортируют `legal_core` как локальный пакет (`pip install -e packages/legal_core`).

## 3. База дел (precedents)

### 3.1 Источники — см. `docs/data-sources.md` (задача T1)
Кандидаты: sudact.ru, сайты районных судов `*.sudrf.ru` (модуль «Судебное делопроизводство», каждый суд отдельно), bsr.sudrf.ru (ГАС «Правосудие»), mos-gorsud.ru, Санкт-Петербургские суды, открытые датасеты судебных решений, статистика Судебного департамента (агрегаты). Цель — как можно больше уголовных приговоров. Перед парсингом каждого источника: robots.txt + условия использования, скорость ≤ 1 запрос / 2 с.

### 3.2 Схема хранения (новые таблицы, отдельная миграция; существующие таблицы не трогаем)

```
source_document
  id PK, source TEXT, source_url TEXT UNIQUE, uid TEXT NULL (УИД дела — ключ дедупликации между источниками),
  court TEXT, region_code TEXT, case_number TEXT, decision_date DATE NULL,
  fetched_at TIMESTAMPTZ, raw_path TEXT, sha256 TEXT UNIQUE, parse_status TEXT
precedent_case
  id PK, source_document_id FK UNIQUE,
  articles TEXT[]            -- нормализовано: '158.2.в', '228.2'
  main_article TEXT, category TEXT (small|medium|grave|especially_grave),
  recidivism TEXT (none|simple|dangerous|especially_dangerous|unknown),
  prior_convictions INT, minor_children BOOL NULL,
  mitigating TEXT[], aggravating TEXT[],       -- коды: '61.1.г', '63.1.а'
  applied_general TEXT[],                     -- '62.1', '64', '68.2', '68.3', '73'
  punishment_type TEXT, term_months INT NULL, conditional BOOL, regime TEXT NULL,
  fabula TEXT, embedding VECTOR(N), extracted_by TEXT, extraction_version INT
INDEX GIN(articles), BTREE(main_article, recidivism), BTREE(punishment_type)
```
Миграционный план: новая ревизия `0003_precedents` только CREATE TABLE/INDEX, downgrade = DROP этих таблиц. Данные пользователей не затрагиваются.

### 3.3 Критерии сортировки/отбора похожих
1. Жёсткие фильтры: та же статья + часть (+ пункт), тот же вид рецидива.
2. Мягкие: категория, наличие ч.1 ст.62 / ст.64 / ч.3 ст.68, наличие малолетних детей, число прежних судимостей, регион, год.
3. Ранжирование: косинус эмбеддинга фабулы + взвешенная дистанция признаков. Top-k = 10.
4. Статистика (медиана, квартили срока, доля условных) считается **в коде** по отобранному множеству, не LLM.

## 4. Приём проекта приговора
`DocumentParser` (Protocol) → infrastructure: `.docx` (python-docx), `.pdf` (pdfplumber), `.txt`.
Валидация (mime, размер, zip-bomb для docx) — в adapters до создания доменных сущностей.
`VerdictSegmenter` (domain service): вводная часть / «УСТАНОВИЛ» (описательно-мотивировочная) / «ПРИГОВОРИЛ» (резолютивная). Нормализация заголовков вразрядку («П Р И Г О В О Р», «У С Т А Н О В И Л»).
Извлечение фактов: regex-слой (статьи, сроки, даты, УИД) + LLM-слой (личность, смягчающие/отягчающие, судимости) с pydantic-валидацией и цитатой на каждый факт.

## 5. Сравнение с LLM
`CompareWithPractice` (use case): DraftFacts + top-k PrecedentCard + результаты rules → `LlmGateway.compare_cases(source, similar) -> ComparisonNarrative`.
В LLM уходят **структурированные карточки**, не полные тексты; ФИО/адреса/даты рождения вырезаны `Anonymizer`.
Промпт (infrastructure/llm/prompts/compare_v1.md): роль — помощник, не судья; вход — карточки; выход — JSON {annotation, deviations[], deeper_analysis[]}; каждая претензия — со ссылкой на норму или номер карточки; запрет придумывать нормы.

## 7. Проверка проекта, версии документов и фактов (T7, T13)

- Разделить обвинение/фабулу и резолютивную часть. Извлекать наказание по каждому составу и итоговое наказание; не путать запрошенное, предложенное и назначенное.
- Сроки, штрафы, удержания, дополнительные наказания, условность и режим имеют единицы измерения и источник. Совокупность преступлений/приговоров и специальные порядки либо поддерживаются отдельными правилами, либо явно исключаются из охвата пилота.
- Оригинал и извлечённый текст сохраняются с хешем; факт ссылается на документ, страницу/абзац, цитату и версию извлечения. Исправление человеком создаёт новую версию, не меняя старые результаты.
- Сейчас запросы независимы и включают собственные вложения. T13 вводит явный выбор версии проекта и набора материалов дела; никаких неявных подстановок старых документов.
- Ограничение контекста 30 000 символов в MR !7 временное. Для полного анализа нужны последовательное извлечение по всем сегментам и сведение фактов с сохранением происхождения. Пока охват неполный, итог не называется полной проверкой проекта.

## 8. Применимость норм и сравнение наказания (T3–T5, T13)

- Юристы утверждают машиночитаемую матрицу поддерживаемых норм: область применения, необходимые факты, редакция/даты действия, исключения, порядок расчёта и эталонные кейсы.
- Пилот сохраняет фокус на рецидиве; проверка УК/УПК за его пределами требует отдельного расширения матрицы. Не заявлять полную проверку всех процессуальных решений.
- Сервис сравнивает извлечённое назначенное наказание с применимой санкцией и ограничениями. Рекомендация модели не служит эталоном законности.
- Статусы: подтверждены условия конкретной проверки / возможное нарушение / недостаточно данных / вне поддерживаемого охвата. Успех отдельной проверки не означает законность приговора целиком.
- Норма, источник, редакция, факты, единицы и промежуточные расчёты входят в результат. Неизвестная редакция, неполная история судимостей или противоречие фактов блокируют уверенный вывод.

## 9. Отчёты и справка (T14, T15)

- Отчёт хранит снимок версии документа, подтверждённых фактов, правил/санкций, отобранной практики и версии модели/промпта. Повторная выгрузка старого отчёта не пересчитывает его незаметно по новой БД.
- Состав: краткий итог, назначенное наказание, проверки и расчёты, спорные места с цитатами, сравнение практики с n/фильтрами, рекомендации и ограничения охвата, отметка проверки человеком.
- Личный раздел отчётов: список, просмотр, привязка к делу, история версий, первый экспорт DOCX. Права проверяются и при прямом скачивании. PDF/другие экспорты — отдельное расширение, а не требование исходного DOCX.
- Справка использует тот же каталог норм и редакций, что расчёты; содержит источники, объяснение поддерживаемых проверок и инструкцию по ограничениям.
- Все новые таблицы/поля — отдельные миграции с backfill и планом обратимости. Имена ревизий в старом плане предварительные: перед реализацией выбирать следующий номер по актуальному Alembic head, а не занимать 0003/0004 вслепую.

## 10. Безопасность и происхождение данных (T9, T10, T17)

- Изоляция по владельцу охватывает дела, файлы, факты, результаты, отчёты и фоновые задачи. Общая база практики отделена от приватных материалов; автоматическое добавление пользовательского дела в общий корпус запрещено.
- До внешней реальной LLM: согласовать политику передачи данных, проверить Anonymizer, отсутствие исходных персональных данных в сетевом запросе и журнале. Локальное соответствие цитат оригиналу хранится приватно и не уходит провайдеру.
- Учесть prompt injection из документов: текст документа — данные, а не команды. Модель не получает права выполнять действия или менять санкции/источники.
- Загрузки: проверка содержимого и MIME, лимитов файла/запроса, zip-bomb, числа страниц и времени/памяти парсера. Возвращать понятные причины отказа, очищать временные файлы.
- Сессии, секреты, TLS при размещении, аудит без текстов дел/секретов, резервное копирование и восстановление, политика хранения/удаления. Конкретные сроки и место хранения не назначаются без ответственного за данные.

## 11. Масштабирование и эксплуатация (T18, T19)

- Устойчивая очередь за TaskQueue: идентификатор/idempotency key, транзакционная постановка, ограниченные повторы, таймауты, восстановление, учёт исполнителя/lease и статус после сбоя. Несколько процессов не сбрасывают чужие активные задачи.
- Согласовать совместимость текущих pending/running с ранее предложенным processing; не менять API и сохранённые статусы без адаптера и миграционного плана.
- Нагрузочный профиль задаётся до теста: одновременные пользователи/задачи, размеры документов/корпуса, приемлемые p95 и время завершения. Затем измеряются очередь, задержки, ошибки, память и восстановление. Значения пока не утверждены.
- Реестр зависимостей/моделей/данных, лицензии, версии, SBOM, проверка совместимости и воспроизводимой установки. Сначала существующий стек; новый компонент очереди/хранилища выбирается после измерений и согласования архитектурной развилки.

## 12. Экспертная оценка и показатели концепции (T12, T20)

- Утвердить независимую экспертную разметку: факты, назначенное наказание, применимые нормы, ожидаемые замечания и релевантные аналоги. Разделить разработочные примеры и контрольный корпус; дубликаты не попадают в разные части.
- Оценивать извлечение фактов, ложные тревоги, пропуски нарушений, корректность норм/цитат, релевантность практики и рекомендации. Отдельно учитывать частично прочитанные документы и отказы; не исключать сложные случаи после просмотра результата.
- Девять приватных образцов — только локальная диагностическая серия; отчёты вне репозитория. Публичные тесты используют синтетические/разрешённые обезличенные материалы.
- Для времени: заранее определить одинаковые задачи и точку окончания работы, провести парное сравнение без системы/с системой с контролем эффекта обучения и порядком прохождения.
- Для ошибок: заранее определить единицу оценки, знаменатель и тяжесть ошибки; независимая проверка и разрешение разногласий экспертов. Снижение времени = 1 − Tсистемы/Tбазовое, снижение частоты ошибок = 1 − Eсистемы/Eбазовое. При нулевом базовом значении относительное снижение не определено.
- До эксперимента определить необходимый n и метод интервалов неопределённости. В отчёте — n пользователей/дел/проверок, абсолютные результаты, доверительные интервалы, условия и ограничения переноса вывода. Сейчас n=0; 40%/70% не подтверждены.

## 13. Приёмка, обучение и внедрение (T21)

Четыре этапа концепции имеют разные результаты: подготовка — согласованный охват/риски; основной — работающий прототип; тестовый — функциональные/экспертные испытания и обратная связь; внедренческий — руководство, обучение, поддержка, резервное восстановление и откат.

Внедрение не происходит автоматически после зелёных тестов: нужны согласованный ограниченный охват, результаты безопасности/лицензирования/нагрузки, учебный сценарий, ответственные за сопровождение и отдельное разрешение пользователя. Невыполненные цели 40%/70% фиксируются как неподтверждённые; публиковать их как результат нельзя.

## 14. Реестр правовых источников (T22, T23)

Отдельный от судебной практики нормативный корпус реализован в ветке feat/legal-library; см. [LEGAL_LIBRARY.md](LEGAL_LIBRARY.md) и [legal-sources.json](legal-sources.json). Снимки хранят исходные байты и SHA-256, источник и время получения; техническая загрузка получает unreviewed. Для ответа «норма на дату» требуются verified и известный период действия конкретной нормы; неоднозначность не разрешается выбором последней записи. Связи legal_core с нормами не создаются автоматически из импортированного текста.

Первый локальный корпус: 8 актов, 1324 блока; действующие/исторические редакции требуют отдельной сверки T23 перед T5 и переводом проверок на БД. Новая ревизия 0003_legal_library занимает следующий head от 0002; будущие precedents/users выбирать от этого head после слияния, не использовать заранее занятые номера. Полный массив законодательства РФ не входит в подтверждённый пользователем объём.
