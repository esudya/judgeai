# Правовая база: первый работающий этап

Запрос пользователя: создать базу законов и источников, на которые опирается проект. Пользователь подтвердил объём: правовая основа уголовного пилота; каталог допускает дальнейшее расширение. Полный массив законодательства РФ не объявляется загруженным.

## Подход

Использовать существующий PostgreSQL/SQLAlchemy/Alembic. Варианты «смешать законы с приговорами в knowledge_verdicts» и «завести отдельную векторную БД» отклонены: первый теряет тип и редакции источника, второй не нужен для точного поиска статьи и даты. Добавить отдельные таблицы в схему приложения. Первую живую загрузку выполнить в отдельную локальную БД judgeai_legal_library, не меняя дела работающего экземпляра.

## Состав

Акт -> неизменяемый снимок редакции -> статьи/пункты с координатами и периодами действия. Снимок хранит официальный URL, фактическое время получения, исходные байты, SHA-256, извлечённый текст и версию парсера. Статус imported_unreviewed отличает техническую загрузку от юридической проверки. Дата загрузки не является датой вступления в силу.

Начальные источники: УК РФ, УПК РФ, Конституция, разъяснения ВС по назначению наказания/приговору/судимости и акты об их изменении. Источники подбираются по найденным официальным карточкам; недоступные тексты остаются незагруженными. Старая или неизвестная редакция не называется действующей.

Правило legal_core связывается с конкретной проверенной версией нормы через отдельную ссылку. Обычный импорт не создаёт такое основание автоматически. Поиск «на дату» отдаёт только проверенные нормы с известным периодом действия, а при неоднозначности отказывает. Интервалы [effective_from, effective_to), открытая правая граница допускается.

## Миграционный план

Новая ревизия 0003_legal_library от текущего head 0002; только CREATE TABLE/INDEX/CONSTRAINT. Существующие chats/messages/attachments/knowledge_* не меняются. Backfill не нужен. Downgrade удаляет только новые таблицы и их загруженные правовые данные; перед downgrade — резервная копия/экспорт. Применение к рабочей БД с делами не входит в текущий локальный запуск. Номера будущих ревизий precedents/users выбираются заново от актуального head.

## Интерфейсы

Публичный read-only API: каталог актов, список снимков, постраничный поиск норм, точная норма на дату с источником/статусом. Импорт — локальная CLI из проверенного манифеста и файлов, без публичного write API. Лимиты текста/страниц/выдачи и проверка схемы на входе; LLM для заполнения закона не используется.

## Готовность

Миграции upgrade/downgrade не затрагивают существующие данные; импорт идемпотентен и проверяет хеш; есть отрицательные тесты дат/редакций/источников/неоднозначности и границ API. Доступные официальные полные тексты реально загружены в локальную БД, количество актов/снимков/норм и пробелы указаны в отчёте. Непроверенные юридически записи не используются движком как действующее право.
