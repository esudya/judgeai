# User Authentication Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline with TDD and one final independent review.

**Goal:** Implement T10 login and case isolation independently of T24–T29.
**Architecture:** Existing stack, additive migration, opaque DB sessions and explicit UserContext.
**Tech Stack:** FastAPI, SQLAlchemy, PostgreSQL, argon2-cffi, React.
**Spec:** docs/superpowers/specs/2026-10-28-user-auth-design.md

## Global constraints
- Preserve old data; no live migration, production deployment, merge or tokens in Git.
- No parser, matcher, legal rules or T24–T29 changes.
- Fail closed for unauthenticated, disabled or expired sessions and unknown ownership.

## Review focus
- Cross-owner message ID and background request/result mismatches must not expose documents.
- Cookie auth requires CSRF; login brute-force attempts are counted atomically in PostgreSQL.
- A default demo/legacy login must never grant access to existing cases.
- Shared knowledge contains unclassified old data; ordinary users cannot search or mutate it yet.
- Dependency/test environment failures are explicit, never reported as passing.
