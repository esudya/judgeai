# Локальные учётные записи — T10

Статус: реализация подготовлена в `feat/user-auth`; **не готова к слиянию до прогона PostgreSQL и проверки интерфейса**. Задачи T24–T29 и код поиска/извлечения не меняются. Рабочая БД и запущенный кабинет этой веткой не обновлялись.

## Поведение

- Учётные записи создаёт оператор локально; публичной регистрации и пароля по умолчанию нет.
- Пароли хешируются Argon2id через `argon2-cffi`; библиотека добавлена в зависимости, собственная криптография для паролей не используется.
- Сессия — случайный токен, в БД только SHA-256, срок 8 часов; cookie HttpOnly, SameSite=Strict, Secure по умолчанию. Выход удаляет сессию, отключённый пользователь теряет доступ. Каждая новая сессия имеет собственное CSRF-значение; изменяющие запросы без заголовка отклоняются. Десять неудачных/одновременных попыток на учётную запись и отдельный бюджет 100 запросов на сетевой адрес за 15 минут. Успешный вход снимает счётчик аккаунта и вычитает свою попытку из сетевого бюджета. Счётчики PostgreSQL атомарные; X-Forwarded-For не считается доверенным. За общим proxy сетевой бюджет общий; доверенные proxy и распределённая политика — следующий этап T17.
- Все маршруты дел, сообщений и результатов требуют входа и владельца. Администратор тоже видит только свои дела через эти маршруты. Неизвестный/чужой ID даёт 404.
- Фоновое задание проверяет владельца и пару запрос/ответ до чтения документов или вызова модели.
- Общая база приговоров пока доступна только администратору: старые записи ещё не классифицированы как общие или частные. Поиск для обычного пользователя выключен; переключатель скрыт. Правовой справочник остаётся общедоступным на чтение.
- Экран входа, выход, имя аккаунта и восстановление состояния по cookie; пароли/сессии не сохраняются в localStorage. Ответы приватных API помечаются `Cache-Control: no-store`.

## Миграционный план

Актуальная цепочка: `0004_criminal_article_sanctions` → `0005_users`.

1. Сделать резервную копию PostgreSQL и загрузок; остановить приём новых запросов/фоновые анализы на время переключения.
2. Пересобрать API с новой зависимостью Argon2 и выполнить `alembic upgrade head` сначала на копии БД.
3. Миграция добавляет users/user_sessions/auth_login_buckets, nullable chats.owner_id и messages.request_message_id. Существующие дела присваиваются **отключённой** записи `__legacy_locked__` без пароля. NULL-владельцы скрыты. Новые дела получают текущего пользователя. Каждый новый assistant-результат связан с конкретным запросом; старым сообщениям связь не угадывается. Фоновый запуск атомарно переводит только pending-ответ своей пары в running, повторный запуск/перезапись завершённого результата отклоняется. Связь request_message_id при downgrade удаляется вместе с auth-полями, сами сообщения сохраняются.
4. Создать пользователя и явно подтвердить принадлежность конкретных старых дел. Только затем запускать обновлённый API/интерфейс вместе.
5. Downgrade снимает ограничения доступа и удаляет сессии/владельцев, сохраняя дела/сообщения/результаты. Это не безопасный автоматический откат: остановить доступ, сохранить резервную копию и согласовать восстановление политики.

Команды в настроенном окружении API (пароль вводится скрыто через getpass, не в аргументах):

```bash
python -m src.cli.users create --username alex --admin
python -m src.cli.users create --username reviewer
python -m src.cli.users assign-legacy --username alex --case-id 12 --case-id 13 --confirm-ownership
python -m src.cli.users disable --username reviewer
```

Назначение атомарно: все перечисленные дела должны принадлежать отключённому legacy-пользователю; случайное присвоение уже принадлежащего другому пользователю дела отклоняется. Секреты и реальные пароли в Git не добавлять.

Для локального HTTP явно задать в игнорируемом `.env` `AUTH_COOKIE_SECURE=false`; для HTTPS оставить true. Указать точные `CORS_ORIGINS`; `*` с cookie-аутентификацией запрещён. Копировать только имена/примеры переменных, не значения токенов DeepSeek.

## Проверки

Выполнено: 5 автономных тестов генерации/разделения токенов, областей лимитов и точной связи запроса/ответа, 7 тестов веб-клиента (включая CSRF и истечение сессии), TypeScript, production-сборка, ruff, Python compileall.

Подготовлены, **не запускались**: интеграционные тесты входа/выхода, блокировки/истечения/перебора, двух пользователей/чужих сообщений и результатов, фонового задания и миграции с сохранением старых дел; полный API regression suite и покрытие. На машине нет backend-зависимостей вне Docker; автоматическая проверка разрешений Docker остановилась из-за лимита использования. Обхода не было. Браузерный запуск также недоступен: desktop/mobile визуальная проверка не выполнена.

Перед снятием Draft: установить зависимости, выполнить полный pytest с покрытием ≥80% на отдельной БД с суффиксом `_test`, сверить upgrade/downgrade и metadata, проверить вход/ошибку/выход/истечение на desktop/mobile, убедиться в отсутствии доступа у второго пользователя и приватных значений в коммите. Не выдавать авторизацию за завершённый T17: остаются анонимизация, MIME/архивные лимиты, TLS, политика хранения, аудит и восстановление.

Источники решений: [Argon2 PasswordHasher](https://argon2-cffi.readthedocs.io/en/stable/api.html), [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
